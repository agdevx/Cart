# Home Page

## Design Spec

### Overview

Add a Home page as the app's new first tab, featuring a greeting panel, a monthly trip calendar with weather integration, and a configurable default landing page. The Home page gives users an at-a-glance view of their shopping patterns alongside weather context for planning trips.

### Page Layout

Two stacked cards on a scrollable single-column mobile layout:

**Greeting Card** — navy gradient background, identical to the existing greeting on the Shopping page:
- Time-based greeting + user's name + wave emoji
- Location label (city from geolocation or manual entry)
- Current weather condition + temperature

**Calendar Card** — white card with:
- Month/year header with left/right navigation arrows
- 7-column day grid (Sun–Sat)
- Weather shown as cell background tints (no emoji in the grid)
- Trip indicators as colored dots below the date number
- Tappable days that open a popover

### Calendar Design

**Date styling by temporal state:**
- Past dates in the current month: dimmed text (`text-secondary`), faded weather tints and trip dots
- Today: bold text, teal inset border, full weather tint
- Future dates in the current month: full-weight text, full weather tint
- Overflow dates from adjacent months: lightest text (`#C5C7D4`), no weather tint

**Weather tints — background color by condition:**
- Sunny: warm yellow (`rgba(254,220,100,α)`)
- Cloudy: cool gray (`rgba(180,200,220,α)`)
- Rain: light blue (`rgba(150,190,250,α)`)

**Temperature as tint intensity:**
- The alpha/saturation of the weather background scales with temperature — warmer temps produce a stronger tint, cooler temps a lighter one
- This provides a rough visual sense of temperature without adding numbers to the grid
- Exact temperature is available in the day popover on tap

**Trip dots:**
- Teal dot: completed trip (has `completedAt`)
- Amber dot: planned trip (has `tripDate`, not completed)
- Multiple dots if multiple trips exist on the same day

**Legend** below the grid showing: Sunny / Cloudy / Rain color swatches + Completed / Planned dot indicators + "Stronger color = warmer temperature" hint.

### Day Popover

Tapping any day opens a popover/modal with:

**Header:** Day name + date + weather emoji + temperature + condition text (e.g., "Mon, March 30 — ⛅ 68°F Partly Cloudy")

**Trip list:** Each trip for that day shown as a row with:
- Shopping cart icon colored by status (teal=completed, amber=planned)
- Trip name
- Status label ("Completed" or "Planned")
- Tapping a trip navigates to its detail page

**"Plan another trip" / "Plan a trip" action:** Always shown at the bottom. Creates a new trip with `tripDate` pre-filled to the selected day.

### Weather Integration

**Provider:** Open-Meteo (free, no API key, CORS-friendly)

**Data fetched directly from the frontend** — no backend proxy needed.

**Two API calls per calendar view:**
- Historical weather: Open-Meteo archive API for dates in the past (up to 1 month back)
- Forecast weather: Open-Meteo forecast API for today + future dates (up to 16 days, which is the API's max)

**Data points needed per day:** weather condition code (maps to sunny/cloudy/rain), high temperature.

**Caching:** TanStack Query with 30-minute stale time. Weather data is keyed by month + location so navigating back to a month reuses cached data.

**Dates outside the weather window** (older than 1 month or more than 16 days ahead): no weather tint, just a plain cell.

### Location

**Geolocation flow:**
1. On first visit to Home page, prompt browser geolocation API
2. If granted: save latitude/longitude to user preferences (backend), resolve to a display name via Open-Meteo's reverse geocoding API (`GET /v1/search?latitude=...&longitude=...`)
3. If denied or unavailable: show a prompt to enter location manually in Settings

**Manual entry in Settings:**
- Text input for city/zip
- Geocode to lat/long via Open-Meteo's geocoding API (also free, no key)
- Saved to user preferences

**Display:** Location shown in the greeting card as "📍 City, State" or "📍 City, Country".

### Navigation Changes

**Bottom nav** gains Home as the first tab (5 tabs total):
- Home | Shopping | Pantry | Household | Settings
- Home icon: house icon from Lucide (`House`)

**Route:** `/home` — added to `routes.ts` as `ROUTES.HOME`

**Root redirect:** `/` now redirects to the user's configured default page (defaults to `/home` for new users).

### Settings Additions

**Default page setting:**
- Dropdown/radio in Settings: Home, Shopping, Pantry, Household
- Stored as a user preference in the backend
- Login flow reads this preference and navigates accordingly
- Defaults to Home if not set

**Location setting:**
- Shows current location (city name + coordinates)
- "Update location" button to re-trigger geolocation
- Manual city/zip text input as fallback
- "Clear location" to remove (weather features gracefully degrade — no tints, just plain calendar)

### Backend Changes

**Trip model — new field:**
- `tripDate` (`DateOnly`, nullable) — the date the user associates with a trip, whether planned or completed
- Existing audit fields (`createdDate`, `modifiedDate`, `startedAt`, `completedAt`) remain but are no longer displayed in the UI as primary date indicators
- Migration adds the column with a default of `null`
- Backfill strategy: set `tripDate = completedAt` for completed trips, `tripDate = createdDate` for non-completed trips

**User preferences — new `UserPreferences` table (one-to-one with User):**
- `defaultPage` (string, nullable) — route path for post-login landing page
- `locationLatitude` (double, nullable)
- `locationLongitude` (double, nullable)
- `locationDisplayName` (string, nullable) — cached city name for display

**New/updated endpoints:**
- `GET /api/v1/user/preferences` — returns user preferences
- `PUT /api/v1/user/preferences` — update default page, location, etc.
- `PUT /api/v1/trip/{id}` — updated to accept `tripDate` field
- `POST /api/v1/trip` — updated to accept `tripDate` field

**Modified files:**

- `shared/bottom-nav/bottom-nav.tsx` — add Home tab as first item
- `pages/shopping/shopping-page.tsx` — remove greeting panel (moved to Home)
- `pages/settings/settings-page.tsx` — add default page and location settings
- `pages/login/login-page.tsx` — navigate to user's default page preference instead of hardcoded `/shopping`
- `app.tsx` — update root redirect to use default page preference

### Graceful Degradation

- **No location set:** Greeting card shows greeting without weather/location. Calendar shows trip dots but no weather tints. A subtle prompt encourages setting location.
- **Weather API failure:** Calendar renders normally without tints. No error shown — weather is supplementary.
- **No trips:** Calendar shows weather tints but no dots. Empty state is just a clean weather calendar.

### Out of Scope

These are planned for future enhancements and are not part of this spec:
- Household activity feed
- Shopping list preview
- Trip templates
- Camera/barcode scanning
